## 1. 适用场景（通用判定）

**适用**：任何由"冲击/释放/碰撞"触发的次级动画，且冲击能量在事件序列中递减或变化：

- 弹跳形变（squash & stretch）
- 落地尘雾、碎屑、火花
- 镜头震动（camera shake）
- 粒子爆发数量/尺寸
- 音效冲击音量/包络
- UI 回弹、按钮反馈
- 破碎/裂纹扩散幅度

**不适用**：持续力驱动的动画（风、重力本身）、恒定源（常亮灯、持续音）。

**判定问题**：这个效果是否由"事件能量"驱动？事件能量是否变化？两个都"是"才用本模块。

## 2. 输入 / 输出

### 输入
```yaml
driver: impact_speed_mps    # 驱动量：冲击速度/能量/动量/峰值力/音量，必须注明单位
events:
  - id: event_01
    time: 20
    value: v0               # 基准驱动量占位符（项目采样后替换；本文件不写死数值）
    anchor: bottom_contact  # 语义锚点（触点/中心/撞击点）
base:
  value: v0                 # 基准事件（通常是第一次/最大一次）
```

> **占位符说明**：`v0` 与 `0.707*v0` 是文档占位符，不是可运算数值；调用 `envelope_check.py` 等工具前必须替换为项目采样得到的驱动量原始值，否则工具无法解析。
>
> **替换示例**（项目侧执行）：若本次采样基准为 B，则把 `v0` → B、`0.707*v0` → 0.707·B，再写入 spec 的 `value` 字段。

### 输出（每个事件的包络参数）
```yaml
- id: event_01
  scale: 1.000              # k = (v/v0)^p
  amplitude: 0.280          # 1 - squash_z（形变深度）
  stretch: 0.075            # pre-stretch 超出 1 的量
  hold_frames: 2
  tilt_deg: 13.5
  window_frames: 8
  cutoff: false
```

## 3. 核心模型

### 3.1 归一化与幂律
```text
s_i = clamp(v_i / v_0, 0, 1)
k_i = s_i ^ p
A_i = A_0 × k_i        # 对每个包络参数分别应用
```

**指数 p 的默认值（按域校准，不是物理常数）**

| 域 | p 默认 | 依据/备注 |
|---|---|---|
| 弹性形变（Hertz 接触） | 0.8 | δ ∝ v^0.8（弹性球近似） |
| 软材料/塑性形变 | 0.6–0.7 | 滞后损耗更大 |
| 镜头震动幅度 | 0.7–1.0 | 艺术校准 |
| 粒子数量/尺寸 | 0.5–0.8 | 性能与可读性优先 |
| 音效冲击响度 | 0.5 | 能量→响度近似 |
| UI 回弹 | 1.0 | 线性缩放即可 |

> p 必须写进模块实例的元数据；不同项目可不同，但不能不写。
>
> **驱动量口径**：上表按 driver = 速度校准（δ ∝ v^0.8）；若 driver 换成能量 E（E ∝ v²），
> 指数要换算：`p_E = p_v / 2`（同例 ≈0.4）。换 driver 必须在模块元数据里写明。

### 3.2 包络形状（每个事件都按同一形状，只缩放幅度与时长）
```text
pre-stretch → peak(squash) → hold → recover → overshoot → settle
```
每段的时长/幅度都乘以 `k_i`；`hold` 取整并做非递增约束。

**关键帧实现契约（V5.2.0 补充，来自实战复盘）**：
- **恒等键**：首帧与每个事件 `f-2` 必须存在恒等键；`pre-stretch` 只允许 1 帧；
  `settle` 必须在**下一事件 `f-2` 之前**回到恒等——否则贝塞尔会把形变 ramp 到整段自由飞行（红线 #34、误区 #105/#106）。
- **接触平台**：dwell 的 `f..f+dwell-1` 每帧写同一个 z 值并保持水平手柄；lift 用**形变后几何**计算
  （倾斜 + squash 的椭球下探），不要先算好抛物线手柄再平移键（红线 #35/#36、误区 #107–#109）。
- **亚帧**：互相抵消的曲线（如脚掌 pitch 与 toe 局部角）必须使用**同一插值方式**，并至少烘焙到 0.25 帧；
  验收用 ≥60fps 的半帧/1/8 帧采样（红线 #38、误区 #111/#112）。
- **验收来源**：`*_measured.json` 必须从交付物采样生成，禁止用生成器常量写 spec（红线 #37、误区 #110）。

### 3.3 截止（cutoff）
```text
if v_i < v_min or A_i < A_min:
    k_i = 0    # 事件不产生次级动画，只保留基础运动（如滚动）
```
`v_min`/`A_min` 按项目定义（例：v_min = 1.0 m/s，A_min = 3%）。

### 3.4 窗口约束（防重叠）
```text
window_i = clamp(round(window_0 × k_i), min=2, max=window_0)
window_i.end ≤ next_event.time - 1
```
若与下一事件冲突，**裁短**，不允许覆盖下一事件的关键帧。

### 3.5 锚点一致性
`anchor` 必须与语义一致：
- 轨迹/路径 → 接地点（bottom contact）
- 旋转/滚转 → 质心（center of mass）
- 镜头震动 → 撞击点或相机

**同一效果里混用锚点 = 语义错误**，必须在模块实例中统一声明。

  value: v0                      # 占位符：项目采样后替换

## 5. 验收断言（必须可机器检查）

```text
[ ] 单调性：squash_depth、stretch、hold、tilt 随事件序号非递增（容差 1e-3）
[ ] 幂律拟合：A_i / A_0 ≈ (v_i / v_0)^p，误差 ≤ 10%
[ ] 截止：v_i < v_min 的事件 amplitude = 0
[ ] 非重叠：window_i.end < event_{i+1}.time − 1
[ ] 锚点一致：所有事件使用同一个 anchor
[ ] 顶部无形变：apex/自由飞行段不出现 pre-stretch/overshoot
[ ] 末端收束：最后一事件之后无残留包络
[ ] 恒等键：首帧与每个事件 f-2 为恒等；pre-stretch 仅 1 帧；settle 在下一事件 f-2 前
[ ] 接触平台：dwell 每帧同一 z；lift 用形变后椭球半轴；无后置平移键
[ ] 亚帧：≥60fps（半帧）与 1/8 帧采样下，接触面穿地 ≤ 容差（建议 ≤0.05mm）
[ ] 验收来源：spec 由交付物采样生成（fcurve/几何），不是生成器常量
```

参考实现：spec 生成 `scripts/sample_esd_from_blend.py`；校验 `toolbox §5 envelope_check.py`。

> **采样器（已实现）**：`scripts/sample_esd_from_blend.py` 从 `.blend` 的
> fcurve / 形态键 / 骨骼 scale 采样生成 measured spec；`envelope_check.py` 仍只校验 spec 内部自洽。
> 用法：`blender -b --python scripts/sample_esd_from_blend.py -- --blend scene.blend --config cfg.json --out spec.json`

## 6. 常见错误（通用，来自真实项目）

1. **只缩放峰值**：squash 缩了，pre-stretch / recover / overshoot / hold / tilt / window 全是常数。
2. **固定窗口套变短间隔**：事件间隔 6 帧、窗口 8 帧 → 重叠、覆盖、apex 形变。
3. **固定 hold**：微事件仍停 2 帧，看起来"卡住"。
4. **clamp 太高**：尾部仍保留 7% 形变，像"用大球模板演小球"。
5. **无 cutoff**：能量趋零仍全套形变，抖动不止。
6. **驱动量选错**：用高度代替冲击速度（h 与 v² 关系），缩放曲线会错。
7. **锚点错**：轨迹采质心却要求贴地；旋转采接地点却要求绕质心。
8. **apex 形变**：预拉伸落进顶点窗口，球在最高点被拉长。
9. **无断言**：只靠肉眼，改参数后回归不可测。
10. **只看单帧**：不看连续帧的形变序列，漏掉"抖动"。
11. **首键晚于首帧**：第一个形变键在接触前 1 帧（如 f19），之前常量外推 → 整段下落都带预拉伸（红线 #34）。
12. **settle 与下一个 pre-stretch 之间无恒等键**：贝塞尔把形变 ramp 到整段飞行，apex 也带形变（红线 #34）。
13. **dwell 的 z 不平**：只给接触帧加 lift、靠暴力穿透补偿抬两端 → 两端悬空、中间下凹；接触 hold 名存实亡（红线 #35）。
14. **lift 公式忽略 squash / 先算手柄再平移键**：补偿公式少算几毫米、等效重力漂移（红线 #36）。
15. **自证式验收 + 整帧验收**：用生成器常量当 spec、只测整数帧 → 报告 pass，产物在 60fps 下穿地/抖动（红线 #37/#38）。
