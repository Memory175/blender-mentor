# 建模与交付质量门（通用）

> 适用：任何 Blender 建模、场景搭建、资产交付、工程/建筑体量、批改与评审任务。
> 目标：把“看起来像”变成“可复现、可检查、边界清楚”。
> **本文件只做模型层检查，不替代结构计算、规范审图、MEP 或施工图。**

## 0. 先定用途与验收

动手前先写清 4 件事；没写清就不要开始堆几何：

1. **用途**：概念沟通 / 视觉出图 / 游戏资产 / 施工前模型 / 工程评审；
2. **范围**：只做外观，还是含室内、结构表达、场地、导出；
3. **验收项**：尺寸、楼层、开口、栏杆、楼梯、相机、文件格式；
4. **专业边界**：结构、防火、无障碍、节能、MEP 由谁复核。

> 规则：**“像”不是验收标准。** 每项至少有一个可检查的数值或文件。

## 1. 坐标、单位、楼层

- 单位统一（建筑常用米），scale 应用；
- 楼层用**参数偏移**，不要在对象坐标里手写 z：
  - `Z1 = Z0 + H1`
  - `Z2 = Z1 + slab`
  - 2F 家具/隔墙/门窗全部基于 `Z2`；
- 每层独立 collection：`Envelope_1F` / `Envelope_2F` / `Furniture_1F` / `Furniture_2F`；
- 隐藏某层出平面时，只隐藏对应 collection，不要靠逐个对象 `hide_render`。

**反模式**：2F 家具直接写 `z=0.8`，结果落在一层；改层高时整屋错位。

## 2. 几何质量（交付前必须过）

| 检查 | 要求 |
|---|---|
| non-manifold | 0（闭合体、开洞不破面） |
| loose vertices | 0 |
| n-gon | 尽量 0；导出游戏/UV 前必须三角化或明确允许 |
| UV | 每个 mesh 至少 1 个 UV layer |
| normals | 朝外一致，单面山墙/屋顶必须加厚或双面 |
| scale | 应用；不要靠 object scale 蒙混 |
| 命名 | 按构件命名，不要 `Cube.001` 交付 |

建议命令/流程：

```text
生成 → 三角化 n-gon → recalc normals → smart UV → 统计 non-manifold/UV
→ 通过后才渲染/导出
```

## 3. 构件关系与净空

只检查“单件好看”不够，必须检查**构件之间**：

- 台阶：平台与门槛齐平，踏步在基础外侧，rise/run 连续；
- 栏杆：高度、杆件净距、底部固定、与楼板/墙的连接；
- 门窗：洞口、窗套、窗台、过梁、玻璃位置与墙厚一致；
- 阳台：悬挑板有支撑/挑梁表达，栏杆不悬空；
- 屋顶：椽木在屋面下，檐沟/落水管连接，屋脊不穿帮；
- 构件之间不能互相嵌入、悬空或留无意义缝隙。

> 住宅栏杆、疏散、防火等数值必须按项目所在地规范复核；模型尺寸不等于合规。

## 4. 相机、出图、可检查性

- **默认相机**必须是主展示视角，保存前重置；
- 至少出：front / iso / detail / plan / interior / night（按任务裁剪）；
- 相机不能进入墙体、柜体、家具内部；近景要检查净空；
- 平面图要隐藏屋顶和上一层，避免“二层家具落在一层平面”；
- 每张图标注是“方案示意”还是“施工图”，不能混用；
- 出图后回看：**这张图能不能看见我声称修好的东西？** 看不见就换机位。

## 5. 交付物

一个可交付的模型至少包含：

```text
xxx.blend
xxx.glb / xxx.obj (+ .mtl)   # 按需
preview_front.png
preview_detail.png
preview_plan.png             # 如任务含建筑/空间
README.md                    # 尺寸、对象数、已知限制、如何打开
```

README 必须写：

- 单位、尺寸、楼层、对象数；
- 默认相机；
- 已做的检查（non-manifold / UV / n-gon）；
- 明确未做的：结构计算、规范、MEP、施工图；
- 生成脚本路径（可复现）。

## 6. 来源与数据治理（模块/规范类任务）

- 模块 `data` 必须有 `source_id`，并登记到 `assets/source_registry.json`；
- `source_id` 缺失、registry 缺失 → **fail**，不是 skip；
- `source_audit` 的 `error` → **ask**，不是 proceed；
- `internal / metadata-only` 只能说明“模块章节存在”，不能当外部权威；
- “最新出版版” ≠ “当地 adopted edition”；规范绑定 jurisdiction + 生效版次；
- `source_refresh` 只提议，不自动替换；官方域名/Crossref 之外不抓。

## 7. 文档、版本、构建一致性

- 版本号只在一个事实源里改（suite/package/README/SKILL 同步）；
- 模块版本、registry hash、`main.md` 模块表必须一致；
- README 的计数（工具数/参考文件数/selftest 数）由实际文件数推导，不手写；
- 构建源文件名必须与构建脚本约定一致，不要用近似文件名或重命名后的旧文件；
- 注入/替换文档时不要跨过 `GITIGNORE`/`CI_YML` 等常量块；
- 加文件后同步：README、load_plan（如需要）、selftest、build 复制列表。

## 8. 反模式清单

出现任意一条，先停下：

- 手写所有 z 坐标，没有楼层偏移；
- 所有对象一个 collection，靠手动隐藏出图；
- 只看渲染图，不查 non-manifold/UV/n-gon；
- 用近景/局部图证明整体正确；
- 保存文件时相机停在临时近景；
- “看起来像房子”就宣布完成；
- 模型里写“符合规范/结构安全”，但没有专业计算/审图；
- 文档计数、版本、截图与实际不一致。

## 9. 交付前 10 问

1. 用途和范围写清了吗？
2. 单位/scale 应用了吗？
3. 楼层偏移参数化了吗？
4. 每层 collection 分开了吗？
5. non-manifold/loose/n-gon 统计过了吗？
6. UV 覆盖率 100% 吗？
7. 门/窗/台阶/栏杆/阳台关系检查了吗？
8. 默认相机正确、没有穿模吗？
9. 交付文件（blend/glb/预览/README）齐了吗？
10. 未做的专业边界写清楚了吗？

> 一句话：**先定验收，再做几何；先过门禁，再出图；不能验证的，明确说不能验证。**
